# QA and demo data

This framework creates disposable Rajeh ERP data for local testing and dedicated QA environments. **Never use it in Production.** It is separate from Production backup and reset procedures and is never invoked by deployment.

The `rajeh:qa-reset` command is registered only when `APP_ENV=testing` or `APP_ENV=qa`. The command and every new demo seeder also check the environment at runtime. Set `RAJEH_QA_DEMO_ENABLED=true`, use a direct MySQL/MariaDB connection, and select an isolated database whose name begins `qa_rajh_`. Demo modes also require an explicit `RAJEH_QA_DEMO_PASSWORD` of at least 12 characters. The guard runs before `migrate:fresh`. The command is absent from Artisan in Production even if the QA flag is set.

These commands **delete and rebuild the selected disposable QA database**:

```bash
php artisan rajeh:qa-reset --empty
php artisan rajeh:qa-reset --catalog
php artisan rajeh:qa-reset --inventory
php artisan rajeh:qa-reset --pos
php artisan rajeh:qa-reset --demo
```

Select exactly one mode. `--empty` migrates and seeds only authorization metadata. `--catalog` adds a QA company, two QA users, branches, stores, products, barcodes, and prices. `--inventory` adds opening stock and transfers. `--pos` adds customers, an outlet shift, a sale and payments, cash movement, and a draft return. `--demo` adds all scenarios, including purchasing and stocktake.

The full dataset has two branches, including Sahil, a branchless warehouse, an outlet mapped to Sahil, and source and destination warehouses. `QA-PRICE-400` has base price 400 and Sahil outlet price 460. The catalog also has barcode-ready products, a zero-stock product, and a product family with two inactive option SKUs generated by the canonical variation action. Purchasing includes a draft and an approved invoice. Inventory includes a received transfer, a draft transfer, and a count with shortage and surplus. The POS sale totals 64, paid 50 cash and 14 card. The QA dataset records a versioned cash-rounding setting of Off through the canonical action so those exact portions settle 64. Factories and Faker supply other sample values. Posting and approvals use the application's actions.

Demo users are `qa-admin@example.test` (`qa-admin`) and `qa-approver@example.test` (`qa-approver`). Both use the password you supplied through `RAJEH_QA_DEMO_PASSWORD`. These accounts exist only in the disposable QA database. Do not reuse a real password.

To add a scenario, extend an existing model factory with Faker and a state where needed, then add a guarded seeder under `database/seeders`. Use application actions for posted financial and inventory records. Add its dependencies to the appropriate mode seeder, and add focused assertions in `tests/Feature/QA/QaDemoDataFrameworkTest.php`. Do not add it to `DatabaseSeeder`, `ProductionSeeder`, a migration, or a deployment script.
