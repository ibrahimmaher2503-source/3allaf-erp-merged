## Root cause and scope safety

`AllocateDocumentNumber::execute()` accepts only a validated active branch context and uses the locked `Branch` model for allocation. Its initialization audit event passed `$branch->id`; the subsequent `document_number_allocated` event omitted `branchId`, leaving `audit_logs.branch_id` null. The corrected writer passes the same validated `$branch->id`. `OverrideDocumentSequenceCounter` now records the sequence's branch only when `scope_type` is `branch`; company-wide sequence overrides remain Global. `SaveInventoryAdjustmentAction` already loads the store and validates its authorized scope, so its audit event now records both `$store->branch_id` and `$store->id`.

No audit query or authorization rule was broadened. The Livewire list and detail remain scoped through `AuditLog::visibleTo`, with the existing gate/policy checks. Focused coverage confirms branch-only and store-only viewers can see the draft, while a viewer scoped to that branch cannot see another branch's event. Company sequence events remain Global. Audit records remain append-only; write-time and viewer-time before/after redaction are unchanged. The view reads only the existing metadata array, adding no relation or database query, so the change adds no N+1 path.

Specific presentation mappings now cover document-sequence create/update, branch sequence initialization, number allocation, sequence override, inventory-adjustment draft create/update, audit export, the numbering category, and the inventory-adjustment source. Existing export configuration, authorization, `visibleTo` scoping, row-limit enforcement, and redaction were preserved.
